# Contracts and Schemas

The single reference for Aideon Desktop's contract families, the Rust-defines/TS-generates rule, the typed IPC command and event surface, the error envelope, generated-schema-as-source discipline, and how time/scenario context and accepted-work envelopes appear in contracts.

---

## The Fundamental Rule

**Rust owns the wire shape. TypeScript consumes generated types. No exceptions.**

Payload structs are defined once in Rust with `serde`. TypeScript types are generated from those definitions. Ad-hoc DTOs or manually mirrored TypeScript shapes that diverge from the Rust source are contract violations. The IPC command surface is the boundary — not HTTP, not a local server.

The manifest of all command names is the executable snapshot: [`./contracts/ipc-manifest.json`](../contracts/ipc-manifest.json) (relative to this file: `../contracts/ipc-manifest.json`). It is generated by `cargo run -p aideon_xtask -- ipc-manifest` and enforced by CI drift checks in both Rust and TypeScript contract test suites.

---

## Contract Families

Aideon Desktop has six contract families. Error-envelope standards apply across all of them.

| # | Family | Description |
|---|--------|-------------|
| 1 | IPC envelope | Request/response wire shape and error envelope |
| 2 | Temporal query context | Time and scenario context carried on every time-aware call |
| 3 | Mneme store operations | Fact writes, reads, and graph queries |
| 4 | Chrona temporal operations | Branching, merging, commits, and diffs |
| 5 | Praxis artefact and workspace | View execution, canvas, layout, templates, and task operations |
| 6 | Accepted-work and events | Long-operation acceptance envelope and progress events |

## 1) IPC Envelope Contracts

Defined in `src-tauri/src/ipc.rs`. All IPC commands use the same request and response shapes.

### IpcRequest

```rust
#[derive(Debug, Clone, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct IpcRequest<T> {
    pub request_id: String,
    pub payload: T,
}
```

JSON on the wire:

```json
{
  "requestId": "uuid-v4",
  "payload": { ... }
}
```

### IpcResponse

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct IpcResponse<T> {
    pub request_id: String,
    pub status: &'static str,
    pub result: Option<T>,
    pub error: Option<IpcError>,
}
```

`status` is either `"ok"` or `"error"`. On success, `result` is present and `error` is absent. On error, `error` is present and `result` is absent.

### Error Envelope

`HostError` maps to `IpcError` at the boundary:

```rust
pub struct IpcError {
    pub code: &'static str,   // stable, machine-readable, snake_case
    pub message: String,      // human-readable, safe for UI display
    pub details: Value,       // structured debug context, defaults to {}
}
```

JSON on the wire:

```json
{
  "requestId": "uuid-v4",
  "status": "error",
  "error": {
    "code": "workspace_not_found",
    "message": "No workspace found for the given identifier.",
    "details": { "workspaceId": "ws_1" }
  }
}
```

#### Stable Error Codes

`code` is a contract-versioned identifier. Changing a code is a breaking change.

| Code | Meaning |
|------|---------|
| `workspace_not_found` | The requested workspace does not exist |
| `workspace_locked` | The workspace is locked by another operation |
| `schema_too_new` | The stored schema version exceeds what this host supports |
| `conflict_recorded` | A scenario conflict was recorded and operation halted |
| `backpressure` | The host job queue is saturated; caller must retry |
| `invalid_input` | Payload validation failed |
| `invalid_time` | A time string could not be parsed or is out of range |
| `internal_error` | An unexpected host-side error occurred |

`details` is structured and optional; it carries machine-readable context for debugging and must not leak secrets or internal stack traces.

## 2) Temporal Query Context

Every time-aware read and write carries explicit temporal context. There are no hidden defaults in handler code.

All payloads that query facts accept:

- `at: String` — valid time as ISO-8601 instant; the time the fact is true in the modelled world
- `asOfAssertedAt: Option<String>` — transaction time as ISO-8601 instant; when the fact was recorded; defaults to now if absent
- `scenarioId: Option<ScenarioId>` — scenario overlay to resolve against; absent means baseline
- `layer: Option<Layer>` — resolution layer; absent means default layer

These fields appear consistently on all mneme store read payloads (`ReadEntityAtTimePayload`, `TraverseAtTimePayload`, `ListEntitiesPayload`, `GetProjectionEdgesPayload`, `ExplainResolutionPayload`, `ExplainTraversalPayload`, and the chrona temporal operations).

All mutation payloads carry:

- `assertedAt: String` — when the fact is being asserted (transaction time)
- `validFrom: String` — when the fact begins being true (valid time)
- `validTo: Option<String>` — when the fact ceases being true; absent means open-ended

See [TEMPORAL-AND-SCENARIO-CONTEXT.md](TEMPORAL-AND-SCENARIO-CONTEXT.md) for the full shape and resolution semantics.

## 6) Accepted-Work and Event Contracts

Long-running host operations do not block the IPC call. They return an `AcceptedJob` envelope immediately and emit typed progress events over the event channel.

### Accepted-work envelope

```json
{
  "jobId": "job_01HXYZ...",
  "acceptedAt": "2026-06-10T09:00:00Z",
  "status": "accepted",
  "eventName": "mneme:job:job_01HXYZ..."
}
```

The renderer subscribes to the event channel using the returned `eventName` to receive progress events.

### Backpressure

When the host job queue is saturated, commands that would start new long-running work return the `BACKPRESSURE` error code rather than accepting the job. Callers must retry with exponential backoff.

### Progress event shape

```json
{
  "jobId": "job_01HXYZ...",
  "status": "running",
  "phase": "projection_rebuild",
  "percent": 42,
  "message": "Rebuilt 1200/3000 entities",
  "completedAt": null
}
```

Terminal statuses: `succeeded`, `failed`, `cancelled`.

See [ACCEPTED-WORK-AND-EVENTS.md](ACCEPTED-WORK-AND-EVENTS.md) for the full envelope shapes, event taxonomy, and cancellation contract.

## Generated-Schema-as-Source Discipline

JSON schemas are the executable contract source. Rust struct definitions generate them; the schemas enforce what the renderer and any tooling consume.

### Generation

```bash
cargo run -p aideon_xtask -- ipc-manifest
```

This regenerates `docs/contracts/ipc-manifest.json` with the current command surface.

### CI drift check

The CI pipeline compares the committed manifest against a freshly generated one. A diff fails the build. The TypeScript contract test suite independently asserts that all commands in the manifest have a corresponding typed adapter. Both checks must pass before merge.

### Change discipline

1. Update the Rust payload struct in the relevant host or engine crate.
2. Regenerate the manifest: `cargo run -p aideon_xtask -- ipc-manifest`.
3. Update the corresponding TypeScript generated types.
4. Update IPC handlers and adapters.
5. Extend contract tests (Rust + TypeScript).
6. Update the affected module `README.md` or `DESIGN.md`.

No ad-hoc TS shapes. No DTOs that exist only in the renderer without a Rust-side source of truth.
